# Filing Requirements Checker

## Overview

New complaints at any level need to know what forms to submit, have certificate
of service, and verification when needed. This skill verifies all filing
requirements before filing.

## Legal Framework

### Certificate of Service

- FRCP 5(b)(2) requires a certificate of service for all filings
- Pa.R.C.P. 1028 requires a certificate of service for all filings
- If a certificate of service is missing, the filing is defective

### Verification

- FRCP 11 requires a signature on all filings
- Pa.R.C.P. 1024 requires verification for certain filings
- If verification is required and missing, the filing is defective

### Cover Sheet

- FRCP 10 requires a cover sheet for certain filings
- Local rules may require a cover sheet for all filings
- If a cover sheet is required and missing, the filing is defective

### Page Limits

- FRCP 15 requires page limits for certain filings
- Local rules may require page limits for all filings
- If a page limit is exceeded, the filing is defective

## Workflow

### Step 1: Determine the filing type and court

Identify the filing type (complaint, motion, appeal, etc.) and the court
(federal, state, etc.).

### Step 2: Query the filing requirements database

The database is at:
`/home/{{USER_FIRST}}/.hermes/skills/legal/filing-requirements-checker/data/filing_requirements.json`

It maps (court, filing_type) → required artifacts. Load it and look up the
requirements for the specific court and filing type.

For example:
- federal_district → complaint → certificate_of_service, verification, cover_sheet, etc.
- pa_state → complaint → certificate_of_service, verification, cover_sheet, etc.
- circuit_court → praecipe → certificate_of_service, verification, signature

The database covers:
- federal_district (10 filing types)
- pa_state (7 filing types)
- circuit_court (4 filing types)
- scotus (2 filing types)

Total: 23 filing types across 4 court types

### Step 3: Cross-reference with Beezle MCP

- mcp_beezle_filing_required_docs — required artifacts for a (court, case_type, filing_type) cell
- mcp_beezle_get_filing_requirements — filing requirements for a specific court and document type
- mcp_beezle_procedural_scan — scan a filing for procedural defects across 4 categories

### Step 4: Build the checklist

For each requirement, document:
- The requirement (certificate of service, verification, cover sheet, etc.)
- The citation (which rule or statute establishes the requirement)
- The status (met or not met)

### Step 5: Fix any defects

For any defect found, fix it before filing:
- Add a certificate of service
- Add verification
- Add a cover sheet
- Reduce the page count

### Step 6: Write to Obsidian

Write the checklist to Obsidian:
    write_obsidian_note(subdir=SUBDIR, filename=FILENAME, content=CONTENT)

### Step 7: Add wikilinks

Add wikilinks to the checklist:
    obsidian_propose_link(from_note=CHECKLIST_NOTE, to_note=CASE_NOTE, edge_type=authority, citation=CITATION)

## Pitfalls

- Don't file without verifying all requirements are met
- Don't assume a requirement is met — verify it
- Don't assume a requirement is not met — verify it
- Don't file without a certificate of service
- Don't file without verification when required
- Don't file without a cover sheet when required
- Don't file without meeting the page limit
