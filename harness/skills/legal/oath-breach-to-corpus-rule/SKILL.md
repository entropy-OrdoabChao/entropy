# Oath-Breach Finding → Corpus Rule Grounding

## Intro

When the user asks to name a judge oath-breach finding from the audit and ground its controlling legal rule in the corpus, this skill captures the three-phase workflow: identify the breach category, map it to corpus search queries, and extract the exact controlling legal rule (quote + source, not just a hit).

## When to Use

- User says "Name ONE judge oath-breach finding from the audit + its ECF"
- User says "Ground the controlling rule for that breach in the corpus (search_chunks)"
- User says "Ground ONE step: search_chunks '[legal term]'"
- User asks to ground a violation category from the audit in the corpus

## Prerequisites

- Audit engine output: `output/audit/data_*.json` (generated by `judicial_oath_breach.py`)
- Corpus service: `http://localhost:8100`
- Order index: `output/audit/orders_*.json`

## How to Run

1. Identify the breach category from the BREACH_MAP or the audit engine
2. Map the category to corpus search queries
3. Query the corpus in sequence, extract the exact quote + source

## Quick Reference

### BREACH_MAP violation categories (from `judicial_oath_breach.py`)

- `NON_BINDING_AS_CONTROLLING` / `TRIAL_COURT_AS_APPELLATE` / `STARE_DECISIS`
- `PRIMA_FACIE_EVIDENCE_IGNORED`
- `TWOMBLY_IQBAL_MISAPPLICATION`
- `CONCLUSORY`
- `BIAS` / `PARTIAL` / `DISQUALIFICATION`
- `DUE_PROCESS` / `NOTICE_INADEQUATE` / `SERVICE_DEFECTIVE` / `DEPRIVATION_OF_RIGHTS`
- `VOID_JUDGMENT` / `RULE_60B4` / `SUBJECT_MATTER_JURISDICTION`

### Corpus Query Endpoints

- `GET http://localhost:8100/search_text?query=QUERY&top_k=N`
- `GET http://localhost:8100/lookup_term?term=TERM&max_hits=N`
- `GET http://localhost:8100/lookup_authority?cite=CITATION`

### Corpus Python Client

```python
from corpus_client import CorpusClient
client = CorpusClient()
results = client.search_text("QUERY", top_k=10)
```

Fallback if corpus_client is unavailable (ModuleNotFoundError):

```python
import subprocess, json
result = subprocess.run(["curl", "-s", "http://localhost:8100/search_text?query=QUERY&top_k=N"], capture_output=True, text=True)
data = json.loads(result.stdout)
```

## Procedure

### Phase 1: Identify the Breach

1. Search for oath-breach findings in the codebase:
   ```
   search_files(pattern="oath.?breach", path="output", output_mode="content", context=5)
   ```

2. Search for judicial_findings in the audit logs:
   ```
   search_files(pattern="judicial_findings", path="output", output_mode="content", context=5)
   ```

3. If search_files returns 0 hits for `data_*.json`, the audit data hasn't been generated yet. Run the audit engine:
   ```
   python -m pipeline.judicial_oath_breach {{CASE_ID}}
   ```

4. Read the BREACH_MAP from `judicial_oath_breach.py` to understand what each violation category means:
   ```
   read_file(path="pipeline/judicial_oath_breach.py")
   ```

5. Name ONE breach finding — pick the category + what the judge did + the source ECF.

### Phase 2: Map to Corpus Queries

Use the BREACH_MAP to determine which corpus queries to run for the controlling legal rule:

- **NON_BINDING_AS_CONTROLLING** → search for "stare decisis lower court not controlling" or "binding precedent only"
- **PRIMA_FACIE_EVIDENCE_IGNORED** → search for "all well pleaded facts accepted true" or "principle established that all well pleaded facts accepted true"
- **TWOMBLY_IQBAL_MISAPPLICATION** → search for "Twombly Iqbal plausibility standard" or "Twombly plausibility standard"
- **CONCLUSORY** → search for "conclusory dismissal without element by element analysis" or "rule 12b6 conclusory"
- **BIAS / PARTIAL** → search for "impartiality reasonably questioned" or "bias partiality"
- **DUE_PROCESS / NOTICE_INADEQUATE** → search for "due process notice requirement" or "due process adequate notice"
- **VOID_JUDGMENT / RULE_60B4** → search for "void judgment rule 60b4 jurisdiction" or "void ab initio"

### Phase 3: Query the Corpus

1. Query the corpus for the controlling rule using the mapped search terms:
   ```
   curl -s "http://localhost:8100/search_text?query=QUERY&top_k=10"
   ```

2. Run multiple queries — the first one rarely contains the exact controlling rule.

3. Extract the exact quote (not just the excerpt) + the source (case name, volume, reporter, page).

### Phase 4: Verify

The skill worked when you can answer: "What is the exact controlling rule in the corpus for [breach category]?" with a direct quote and its source citation.

## Pitfalls

- **corpus_client import error**: The corpus-client module may not be available in the sandbox. Always have a curl fallback ready.
- **Search timeout**: search_files may return `search_timeout` — retry with a narrower pattern.
- **Don't stop at the first hit**: The corpus is 35.6GB, so the top result may be tangentially related but not the controlling rule for this specific violation type.
- **Don't summarize the rule**: The user needs the exact quote + citation, not your paraphrase.
- **BREACH_MAP is the source of truth**: Do not guess at what each violation category means — read the BREACH_MAP from `judicial_oath_breach.py`.
- **session_search context**: When searching session history, the tool returns truncated output. Use `session_search(around_message_id=..., window=10)` to scroll in the session for more detail.
- **Oneshot mode**: When in oneshot mode, you may need to pick the best option from choices without user confirmation.

## Verification

After grounding the controlling rule and extracting the quote + source, verify the citation is real by checking it against the corpus:

```
curl -s "http://localhost:8100/search_text?query=CITATION_KEYWORDS&top_k=5"
```

If the query returns hits that reference the same case name and page, the citation is likely real.
