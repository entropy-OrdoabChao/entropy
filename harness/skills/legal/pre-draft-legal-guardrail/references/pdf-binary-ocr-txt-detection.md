# Pattern 18: PDF Binary Misnamed as .ocr.txt — Reference

**Session:** 2026-06-22 cron intake processing (Pattern 18 introduced)

## Problem

`.ocr.txt` files in intake folders can be PDF binaries (not OCR text). The agent must check binary header before treating as text sidecar.

## PDF Header Formats to Detect

### Format 1: Standard PDF
```
%PDF-1.4\n%
```
First 5 bytes: `b'%PDF-'`

### Format 2: Version-header PDF (LF)
```
1.4\n%\n\n<</Title
```
First 20 bytes: version number (e.g., `1.4`), newline (`\n`), percent sign, newline, then PDF objects.

Common in PDFs generated by:
- Skia/PDF m141 Generator
- Mozilla/5.0 PDF generation
- Chrome/PDF export

### Format 3: Version-header PDF (CRLF) — CRITICAL EDGE CASE
```
1.6\r\n%\n\r<</Linearized
```
First 10 bytes: version number, carriage return + newline (`\r\n`), percent sign, carriage return, newline, then PDF objects.

**NOT DETECTED by Format 2 check** — the `\r` before `%` breaks the `\n` match.

Common in PDFs generated by:
- Microsoft Word PDF export
- Windows-based PDF generators
- Gmail attachments (Outlook/Chrome PDF export)

## Detection Code

```python
with open(fpath, 'rb') as fp:
    header = fp.read(20)

is_standard_pdf = header[:5] == b'%PDF-'
is_version_lf = header[0:1].isdigit() and header[3:4] == b'\n' and header[4:5] == b'%'
is_version_crlf = header[0:1].isdigit() and header[3:4] == b'\r' and header[4:5] == b'%'

if is_standard_pdf or is_version_lf or is_version_crlf:
    # PDF binary — use pdftotext
    pass
else:
    # Text sidecar — read as text
    pass
```
