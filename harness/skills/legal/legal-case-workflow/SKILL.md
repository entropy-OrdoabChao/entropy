# Legal Case Workflow

## Overview

No single skill is enough. The master workflow ties all skills together:
corpus query → definition builder → remedy discovery → filing strategy →
Obsidian persistence → self-learning loop.

## Master Workflow Pattern

### Phase 1: Discovery

1. **corpus-query** — Query the corpus for the legal text
2. **legal-definition-builder** — Build definitions for key terms
3. **remedy-discovery** — Find all remedy avenues under the statute
4. **web-remedy-search** — Web search for remedies outside the corpus
5. **cross-reference-index** — Find related statutes, remedies, definitions, and cases

### Phase 2: Analysis

6. **statutory-construction-analyzer** — Apply rules of construction
7. **authority-hierarchy-builder** — Map which authorities bind which courts
8. **case-law-discovery** — Find relevant case law
9. **opposing-counsel-challenge** — Find defects in opposing counsel's filings
10. **jurisdictional-hat-swapping-detector** — Detect hat-swaps by judges

### Phase 3: Filing

11. **filing-requirements-checker** — Verify all required forms, certificates, and verification
12. **filing-strategy-builder** — Determine optimal sequence and type of filings
13. **beezle-mcp-routing** — Use MCP tools for workflow

### Phase 4: Claims (suing judges, opposing counsel, agencies)

14. **qualified-immunity-analyzer** — Build 1983 claims against judges
15. **utpcpl-consumer-protection-analyzer** — Build UTPCPL claims against opposing counsel
16. **judicial-conduct-complaint-builder** — Build judicial conduct complaints
17. **foia-privacy-act-analyzer** — Build FOIA and Privacy Act claims
18. **constitutional-claim-builder** — Build constitutional claims at any level
19. **bonds-insurance-remedy** — Build financial remedies against judges/courts
20. **insurance-law-analyzer** — Build insurance law claims (Coverage E, bad faith, etc.)
21. **ucc-banking-analyzer** — Build UCC and banking law claims
22. **financial-law-analyzer** — Build comprehensive financial law claims
    (federal reserve credits vs debt, IRS forms, ledger balancing, securities law, etc.)

### Phase 5: Persistence

20. **obsidian-knowledge-persistence** — Write discovered patterns to Obsidian
21. **obsidian-link-maintenance** — Maintain wikilinks when writing to Obsidian
22. **obsidian-search-optimization** — Use the Obsidian graph to find related knowledge
23. **obsidian-orphan-detection** — Find and fix orphaned notes

### Phase 6: Self-Learning

24. **self-learning-loop** — Track outcomes and feed them back
25. **cross-case-pattern-detector** — Identify recurring issues across cases

## Example: FCRA case with 93 fatal violations

1. corpus-query: GET /search_text?query=FCRA 15 USC 1681 violation pattern
2. legal-definition-builder: GET /lookup_term?term=furnisher
3. remedy-discovery: GET /search_text?query=FCRA 15 USC 1681 damages remedy
4. web-remedy-search: web_search for FCRA remedies
5. statutory-construction-analyzer: analyze "means" vs. "includes"
6. authority-hierarchy-builder: classify opposing counsel's citations
7. case-law-discovery: GET /search_text?query=FCRA case law
8. opposing-counsel-challenge: challenge 988 F.2d 476
9. filing-strategy-builder: recommend_filing_types
10. beezle-mcp-routing: compose_and_draft
11. qualified-immunity-analyzer: build 1983 claim against Judge {{JUDGE}}
12. obsidian-knowledge-persistence: write to definitions_learned/
13. obsidian-link-maintenance: add wikilinks to the note
14. self-learning-loop: register_outcome
15. cross-case-pattern-detector: search for judge {{JUDGE}} patterns

## Pitfalls

- Don't skip a phase — each phase builds on the previous one
- Don't use a skill without first querying the corpus
- Don't assume a skill is correct — verify against the corpus
- Don't skip persistence — write discovered patterns to Obsidian
