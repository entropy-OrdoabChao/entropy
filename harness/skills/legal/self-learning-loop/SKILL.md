# Self-Learning Loop

## Overview

Every legal action has an outcome — success, failure, or partial success.
This skill tracks those outcomes and uses them to improve future actions.

## Workflow

### Step 1: Record the outcome

After every legal action, record:
- What action was taken
- What outcome was achieved
- What went wrong (if anything)
- What went right (if anything)
- What should be done differently next time

### Step 2: Query the corpus for similar past outcomes

    GET http://localhost:8100/search_text?query=SIMILAR+OUTCOME+statute+result&top_k=10

### Step 3: Cross-reference with Beezle MCP

- `mcp_beezle_register_outcome` — log a filing outcome to the learning loop
- **NOTE:** `mcp_beezle_memory_set` and `mcp_beezle_memory_get` DO NOT EXIST on the live MCP server. Use the hermes-native `memory` tool instead:
  - Write memory: `memory_set(agent_slug, body="...", append_log="...")`
  - Read memory: `memory_get(agent_slug)`

### Step 4: Update the strategy

Based on the outcome and corpus data, update the strategy for future actions.

## Key patterns

### Recording outcomes

- Success: record what worked, why it worked, and how to replicate it
- Failure: record what went wrong, why it went wrong, and how to avoid it
- Partial success: record what worked, what didn't, and how to improve

### Querying the corpus for similar outcomes

- Search for the statute + outcome (e.g., "FCRA damages awarded")
- Search for the citation + outcome (e.g., "988 F.2d 476 outcome")
- Search for the judge + outcome (e.g., "{{JUDGE}} EDPA outcome")

### Updating the strategy

- If a strategy worked, document it and use it again
- If a strategy failed, document why and try something different
- If a strategy was partially successful, document what to improve

## Example: Motion to strike granted

1. Record outcome: Motion to strike granted — opposing counsel cited non-binding
   9th Circuit authority
2. GET /search_text?query=988 F.2d 476 motion to strike outcome
3. Register outcome: mcp_beezle_register_outcome(case_id, outcome="granted")
4. Update strategy: Always verify opposing counsel's citations before responding

## Pitfalls

- Don't skip recording outcomes — they are the most valuable data
- Don't assume a past outcome will repeat — verify the law each time
- Don't assume a past strategy will work again — verify the facts each time
- When in doubt, query the corpus directly rather than relying on memory

## Active retrieval (use the shadow-study skill) — raises accuracy
Before recording a learning, run the shadow-study loop instead of passively retrieving:
1. RECALL from memory FIRST — write what you think the term/rule/doctrine means + your CONFIDENCE (high/med/low). Do NOT search yet. Label it a PREDICTION (not grounded).
2. VERIFY — now search_chunks / read_graph and compare.
3. Record ONLY the GAP where memory diverged (wrong / missing / low-confidence-but-actually-X). That gap is the hallucination point; the cited gap-correction is the high-value learning — not a re-summary of what you already knew.
Keep it one small topic per cycle and LINK the gap-note. See the shadow-study skill.
