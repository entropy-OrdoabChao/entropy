# Beezle cron operating doctrine (every job follows this)

1. CONTEXT-SAFE: do ONE small step per run; never read whole manuals/dockets; stop after the step. Build over nights.
2. GROUND + CITE: use ONLY the corpus/DB/record/Obsidian vault; cite every authority; never invent a citation, definition, or fact.
3. DEFINITIONS = BOUNDARIES: pin disputed terms to the controlling definition (means=closed / includes=expansive) and the referent (legal entity vs natural individual; "you" may = the institution) BEFORE reasoning. Pull the definition SEMANTICALLY (mcp_beezle_search_chunks — NEVER keyword/FTS, which gives false negatives) from a law dictionary (Bouvier's Law Dictionary) + banking-law + the controlling statute/regulation; never substitute an ordinary English dictionary, never collapse a multi-word term. If genuinely absent, write NOT IN CORPUS. Use/extend the definition graph in legal/definitions/ with [[wikilinks]]. SYNCHRO RULE: the corpus already HOLDS the full definition - do NOT rewrite it into Obsidian. Record your SYNTHESIZED CONCLUSION - what the term/authority MEANS, how it CONNECTS to the other authorities (the cross-authority money-flow), and which active case it bears on; THIS synthesis is the learning and is NOT in the corpus, so it must be preserved in full. Then add a STRUCTURED, followable pointer so the link lets any LLM pull the full text from the DB fast: include the controlling cite AND its corpus coordinate (source doc + chunk id from the search_chunks hit). Paste verbatim primary-source text ONLY for a NOT IN CORPUS gap (nothing to point at). NEVER reduce a note to a bare cite: the synthesis stays, only the verbatim statute/definition block is replaced by the pointer (the DB holds it verbatim and better).
4. HIERARCHY: know which authority controls (binding>persuasive, specific>general, UCC Art 3 vs 9, UCC vs common law per 1-103, statute vs 1 U.S.C. 1).
5. REBUT BEFORE CONCLUDING: lay out the candidate conclusions, attack each from the sources, loop until no doubt; when several survive, name the discriminating link that makes one truer. State residual doubt honestly.
6. THINKING: off for mechanical/extraction work; on for reasoning (set by the provider routed to this job).
7. PERSIST TO OBSIDIAN — CONNECTED, NOT BLIND: write your finding to its topic log AND append it as one line to output/learnings.jsonl ({"text": <SHORT grounded finding + which active case(s) it bears on>, "cite": "<controlling authority + corpus coordinate: source doc / chunk id>", "tags": [...], "source": <job>}). That JSONL line is what pipeline/connected_notes.py turns into a linked atomic note — a note written only under studies/ or comprehension/ without the JSONL line risks staying blind. Always name the active case(s) the finding applies to (read meta/CASE_GROUND_TRUTH.yaml).
8. NO INVENTION / NO PSEUDOLAW: conclusions follow the cited authorities, not preference.
9. NO FIRST-HIT / NO FIRST-WIN (user-corrected 5x, locked 2026-09-03): the first confirming find is the START of the pass, not the deliverable. Finish the WHOLE assigned scope before reporting — all billers not one industry, all sections flagged by a sweep OPENED, all cycles/documents in a set examined. Domain analyses are AGNOSTIC by default (utility/card/medical/telecom/mortgage alike); a single-industry framing of a general question is a defect. Partial completion is reported as partial, never as done.
